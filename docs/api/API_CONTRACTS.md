## POLICY COPILOT API

### POST `/api/v1/ai/policy-copilot`

| Field | Value |
|-------|-------|
| **Method** | POST |
| **Path** | `/api/v1/ai/policy-copilot` |
| **Auth** | Required — `protect` + `requireRole('government', 'admin')` |
| **Rate Limit** | `aiLimiter` (100 req/min) |

**Request Body:**
```json
{
  "query": "What is the overall employment transition rate in Maharashtra?"
}
```

**Query Validation:**
- `query` — string, required, 5–2000 characters
- Injection delimiters (`<system>`, `[INST]`, etc.) are stripped from user text

**Success Response (200):**
```json
{
  "success": true,
  "data": {
    "answer": "**Key Finding**: ...",
    "citedMetrics": [
      {
        "label": "Overall Employment Transition Rate",
        "value": "65%",
        "context": "Across 1200 trainees"
      }
    ],
    "suggestedInterventions": [
      {
        "title": "Employment Transition Acceleration",
        "action": "Current transition rate is 65%. Prioritize...",
        "priority": "HIGH"
      }
    ],
    "confidence": 0.94,
    "dataSufficiency": "sufficient",
    "limitations": []
  },
  "message": "AI Policy intelligence response generated"
}
```

**Error Responses:**
- `400` — Query missing, too short (< 5 chars), or too long (> 2000 chars)
- `401` — Not authenticated (no token or invalid token)
- `403` — Role is not `government` or `admin`
- `429` — Rate limit exceeded
- `500` — Policy copilot query failed (AI provider error or internal error)

**Data Sources:**
- `outcomeService.getOutcomeFunnel()` — enrollment, placement, retention counts
- `outcomeService.getDistrictIntelligence()` — district-level employment rates
- `outcomeService.getWageProgressionAnalytics()` — salary progression data
- `outcomeService.getRelevanceAndBarrierAnalysis()` — non-placement reasons, training relevance
- `dataQualityService.calculateDataQualityScore()` — verification rates, follow-up rates

**Security:**
- Database metrics are wrapped in `<DATA>` tags in the prompt
- AI is instructed to treat DATA as untrusted content
- User input is sanitized against prompt injection delimiters
- Response contains no PII — only aggregate statistics

## AI CHAT API

### POST `/api/v1/ai/chat`

| Field | Value |
|-------|-------|
| **Method** | POST |
| **Path** | `/api/v1/ai/chat` |
| **Auth** | Optional — `optionalProtect` (works for guests and authenticated users) |
| **Rate Limit** | `aiLimiter` (100 req/min) + per-user 60 req/hr |

**Request Body:**
```json
{
  "message": "What skills should I learn for React?",
  "history": [
    { "role": "user", "content": "Hi" },
    { "role": "assistant", "content": "Hello! ..." }
  ],
  "context": "Student on SkillSense AI platform"
}
```

**Response:** Server-Sent Events (SSE) stream
```
data: {"chunk":"React "}
data: {"chunk":"is "}
data: {"chunk":"a "}
data: {"done":true,"suggestions":["What skills should I focus on next?",...]}
```

**Error Responses (SSE):**
```
data: {"error":"AI service is currently unavailable.","done":true}
```

**Entitlements Check:** Server-side — checks `aiRequests` quota against user's plan.

## OTHER AI ENDPOINTS

### POST `/api/v1/ai/analyze-skills`
- **Auth**: Required (`protect` + `aiLimiter`)
- **Body**: `{ text?, githubUrl?, projects?, skills?, program?, nsqfLevel? }`
- **Returns**: Skill analysis with scores, strengths, weaknesses, recommendations

### POST `/api/v1/ai/assess-skill`
- **Auth**: Required (`protect` + `aiLimiter`)
- **Body**: `{ topic: string, level?: string }`
- **Returns**: 5 MCQ questions with options, correct answers, explanations

### POST `/api/v1/ai/assess-skill/evaluate`
- **Auth**: Required (`protect` + `aiLimiter`)
- **Body**: `{ topic: string, answers: QuestionAnswer[] }`
- **Returns**: Score, weak areas, strengths, improvement plan

### POST `/api/v1/ai/predict-career`
- **Auth**: Required (`protect` + `aiLimiter`)
- **Body**: `{ skills: Skill[], interests: string[], education: string }`
- **Returns**: Top career paths with match %, salary ranges, roadmaps

### GET `/api/v1/ai/market-trends?skill=React`
- **Auth**: None (public)
- **Returns**: Market demand, top employers, salary range, trending topics
- **Cache**: 1 hour in-memory

### GET `/api/v1/ai/assessment/:id`
- **Auth**: None (public)
- **Returns**: Assessment details with AI analysis

### GET `/api/v1/ai/history`
- **Auth**: Required (`protect`)
- **Returns**: Chat history for the authenticated user

### POST `/api/v1/billing/checkout`

| Field | Value |
|-------|-------|
| **Method** | POST |
| **Path** | `/api/v1/billing/checkout` |
| **Auth** | Required (`protect`) |

**Request Body:**
```json
{
  "plan": "growth",
  "billingCycle": "monthly"
}
```

**Validation:** `plan` must be one of `free|starter|growth|enterprise`. `billingCycle` must be `monthly|yearly`. **No price field accepted** — server reads from `plans.ts`.

**Response (200):**
```json
{
  "success": true,
  "data": {
    "subscriptionId": "demo_sub_abc123...",
    "demoMode": true,
    "redirectUrl": null
  },
  "message": "[Demo] Successfully subscribed to Growth (monthly). No real payment was charged."
}
```

**Error Responses:**
- `400` — Invalid input, enterprise plan (requires sales contact)
- `500` — Checkout failed

### POST `/api/v1/billing/webhook`

| Field | Value |
|-------|-------|
| **Method** | POST |
| **Path** | `/api/v1/billing/webhook` |
| **Auth** | None (signature-verified) |
| **Headers** | `x-billing-signature` |

**Request Body:** Provider webhook event (provider-specific)

**Response (200):**
```json
{ "success": true, "data": null, "message": "Webhook received" }
```

**Idempotency:** Duplicate event IDs (via `body.id` or `body.event_id`) return success without re-processing. Events are cached for 24 hours.

**Error Responses:**
- `401` — Invalid webhook signature
- `500` — Webhook processing failed

## PLAN / ENTITLEMENT RULES

| Plan | Price (Monthly) | Price (Yearly) | Max Trainees | Max AI/mo | Max Assess/mo | Policy Copilot |
|------|----------------|----------------|--------------|-----------|---------------|----------------|
| Free | ₹0 | ₹0 | 10 | 20 | 5 | No |
| Starter | ₹1,999 | ₹19,990 | 100 | 200 | 100 | No |
| Growth | ₹4,999 | ₹49,990 | 500 | 1,000 | 500 | Yes |
| Enterprise | Custom | Custom | Unlimited | Unlimited | Unlimited | Yes |

**Bypass Roles:** `government`, `student`, `admin` roles bypass all entitlement checks and receive enterprise-level access.

**Server-Side Enforcement:** The `entitlementService.getEntitlements()` method is called server-side. Client cannot manipulate plan, price, or entitlements.

**Demo Mode:** All billing operations run through `DemoBillingProvider`. No real payment is processed. All responses include `demoMode: true` or explicit `[Demo]` prefix.
